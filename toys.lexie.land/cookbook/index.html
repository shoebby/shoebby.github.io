Recurse³ is a binary fractal tree generator, constructed with <div> elements and styled with CSS. It can make for some compelling effects!

Its interface is relatively straight-forward compared to the other tools, but the number of options can be a bit overwhelming. We'll go over them one by one, after which I'll share some of my yummy delicious recipes...

Branches

Branches make up the tree structure. They are <div> elements generated through JS, and positioned/styled with CSS.

Generation

The Starting Values influence the angle and length of the first branch, also called the 'root'. Its starting values are 150 pixels long and -90 degrees for a basic upright tree.

The Angles decide at what angle the splitting branches should diverge. These values can both be randomized as well within a set range.

The Ratio is the value that following branches are multiplied with. So for example, a starting length of 200 pixels with a Ratio of 75 means the next two branches will be 150 pixels long.

The Depth sets the number of 'splits' that take place. It's set to a maximum value of 12 for performance reasons, any higher than that will, unfortunately, just make the browser crash!

Branch generation settings as seen in Recurse³

Styling

Width controls the thickness of the branches, and they can be set to a few different modes: Consistent Width makes the Width of every branch the same value.
  • Width == Length makes the Width of every branch equal to its Length.
  • Depth-Based Width makes the Width of branches taper off per split, creating a relatively natural, or 'veiny' looking tree. The input value applies to the root and shrinks from there.
  • Randomized Width randomizes the Width of every branch individually.

Depth-Based Width's veinyness on display, kind of gross?

Corner Rounding, in CSS also known as 'border-radius', rounds off the corners of branches in pixels. They all start off rectangular, but can become oval or round when these values are raised to something like '999'.

Combining Corner Rounding with a Radial Gradient Background and Inset Shadow can create a faux-3D orb effect.
Kind of looks like that interactive buddy flash game...

An example of the color-burn Background Blend Mode mixing a Radial and two Linear Gradient Backgrounds to create a trippy, phaser-y visual effect.
Never underestimate what some basic CSS can achieve!

Background contains a variety of functions, but in essence it's what 'colours in' the branches.
  • Depth-Based makes the colour of the branch change step by step, using the operating system's built-in colour picker.
  • Background is the field in which you write CSS, for example colours, gradients, or maybe even an image URL.
  • Background Blend Mode sets the blend mode of the different background layers. It does nothing if you have one even colour, but does something when you layer a radial and a linear gradient for example.
  • Mix Blend Mode sets the blend mode of the branch as a whole, and lets it interact with the background and the other branches.

Border brings some cel-shaded depth to this cactus.

Border surrounds each branch with a width-set, coloured border of a certain type. There is a variety of types to choose from listed above the input field, and types can be combined. For example a border type of 'solid none none none' will create a sort of 3D effect.
Shadow makes each branch cast a shadow.
  • Mode features inset and outset, which positions the shadow either inside or outside of the branch.
  • X and Y Offset shift the position of the shadow along these two axes.
  • Blur sets how many pixels wide the transition between transparency and the shadow colour is.
  • Spread sets how many pixels the shadow should expand from the initial branch's size. Can be a negative value!
  • Colour... sets the shadow's... colour... Duhh.

An alternative use for Shadow is to make glow effects, which is entertainingly antonymous.
Here a sort of angelic, art-deco neon symbol is achieved with an orange Shadow, the screen Mix Blend Mode, and Angles set at 135 degrees.

Flowers

Flowers are additional <div> elements positioned along a given branch. They can be generated, positioned, and styled in a number of ways.

Generation

Flower generation options, as seen in Recurse³

Flowers can be generated in three modes, Flat, Randomized, and Capped.
  • Flat generates a flat amount of flowers on every branch, and this number can be set.
  • Randomized generates a random number of flowers per branch, within a set range.
    For example setting Minimum Amount to 2 and Maximum Amount to 8 ensures that every branch features at least 2 flowers, and no more than 8, with variety between the different branches.
  • Capped generates a flower on each branch within a certain depth range.
    For example, to achieve the look of a natural tree, you may want to set the Minimum Depth to 1 (meaning the endmost branches), and the Maximum Depth to something like 5. This way you can get a nice canopy going!
Positioning is another flower generation setting, which dictates the branch-relative surface area where flowers can bloom.
You can set the Minimum and Maximum along the branches' Length, and the Minimum and Maximum along the branches' Width.
For example, if you wish to position your flowers in the middle of the tippy end of a branch, these values would be 100, 100, 50, and 50 respectively.

Setting Minimum values below 0 and Maximum values over 100 makes for floating flowers, which can here be seen used to create fireflies!

Styling

A cloud of blocks, made with Randomized Width and Height, and a double, red Border. Reminds me of the Number World in Yume Nikki somewhat.

Flower styling is largely identical to that of branches, however it does offer the additional styling parameter of Height. This quite simply, much like Width, affects the size of the flowers, either to a flat or a randomized value.

Note: When using images as branch backgrounds, it's good to be aware that if the image gets taken offline, it'll cease to function as a background. Typist is the word processor of VisunovOS. It features various text styling incantations, some of which even make the text move!

It works by highlighting a section of text and then pressing the desired incantation, which are generally able to stack onto one another if they don't directly override each other.

Be warned that Typist is quite buggy and prone to break your text! For example in the sentence:
"Good dogs are good, bad dogs are bad."
Highlighting the final 'bad' and applying an incantation to it will instead style the first-most occuring 'bad', which is unintended and at times annoying.

Practice some patience, and if you want to add your own incantations to Typist go to section 6 of the Toymaker Guides!

Adding A Desktop Toy

  1. Navigate to index.html in the root directory.
  2. Under guyMode and spinny, create a new < a > element with a similar structure as the other desktop toys.
  3. Set the target attribute and second class of your toy to something short and descriptive, for example greyout.
  4. Write a name in the < p > element with the folderName class, this is what be the text that appears under the toy icon.
    You should end up with something like:
    < a target="greyout">< div class="static greyout">< p class="folderName">Old-Timey< /p>< /div>< /a>
  5. Save and navigate to index.js in the root directory.
  6. Create a query selector that targets the < a > element and attaches a click event to it, which then triggers a function called something similar and descriptive to the HTML element you just created.
    For example:
    document.querySelector("a[target='greyout']").addEventListener('click', (event) => { Greyout() });
  7. Creat an accompanying function that does the thing you want your desktop toy to do. For example:
    function Greyout() {
     let allDivs = document.querySelectorAll("div");
     for (let i = 0; i < allDivs.length; i++){
      if (allDivs[i].classlist.contains("oldtimey") {
       allDivs[i].classlist.remove("oldtimey");
      } else {
       allDivs[i].classlist.add("oldtimey");
      }
     }
     playAudio("./sounds/webtoys/oldtimey.mp3");
    }
  8. Note: This setup is for desktop toys that immediately do something when clicked. Alternatives, like toys that have their own window pupup for example, are possible but require more work. The settings window is a good reference for something like that.
